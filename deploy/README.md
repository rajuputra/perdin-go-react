# Deployment DinasFlow

Target publik: `https://dinasflow.rajuportofolio.web.id`.

- Gunakan Compose dengan nama proyek `dinasflow`. Siapkan file environment di VPS dengan izin `0600`. Salin nama variabel dari `.env.example` dan isi `DINASFLOW_DB_PASSWORD` serta `DINASFLOW_JWT_SECRET` dengan nilai acak baru yang berbeda. Keduanya dapat dibuat dengan `openssl rand -hex 32`. Jalankan `docker compose --env-file <file> -p dinasflow up -d --build --wait`.
- Stack hanya mengikat web ke loopback pada port 15082 secara default. Tambahkan DNS untuk subdomain dan rute HTTPS pada reverse proxy yang sudah menangani port 80/443. Jika reverse proxy berada di dalam container, hubungkan ke jaringan stack yang sesuai dan arahkan ke `web:8080` melalui nama layanan yang unik di jaringan bersama. Loopback container menunjuk ke container itu sendiri. PostgreSQL dan API tidak memerlukan port publik.
- Sebelum menerima pengguna, buat admin awal memakai `docker compose --env-file <file> -p dinasflow exec -T -e ADMIN_USERNAME=<username> api /app/dinasflow init-admin`. Berikan kata sandi melalui stdin dari penyimpanan yang aman. Perintah hanya berlaku jika belum ada administrator. Reset akun dilakukan oleh admin pada Master User setelah memverifikasi identitas, lalu menyampaikan kata sandi melalui kanal privat.
- Periksa `/api/health` (204), akses langsung ke `/login`, serta alur login, pengajuan pegawai dan keputusan SDM pada HTTPS. Cookie produksi memakai flag Secure dan HttpOnly.
- Sebelum memutakhirkan database yang berisi data, simpan dump di lokasi privat dengan `docker compose --env-file <file> -p dinasflow exec -T db pg_dump -U dinasflow -d dinasflow -Fc > dinasflow.dump` dari shell Linux. Uji pemulihan dengan `pg_restore` pada database kosong yang terpisah. Simpan image rilis sebelumnya bersama backup. Jika rollback memerlukan pemulihan skema, pulihkan ke database terpisah dan ambil keputusan atas data yang ditulis sejak backup sebelum mengganti target database. Jangan hapus volume aktif.
- File `.env` pernah masuk riwayat Git. Rotasi setiap kredensial lama di lingkungan yang masih memakainya. Penghapusan dari indeks Git tidak menghapus salinan historis.
